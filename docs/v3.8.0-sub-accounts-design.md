# RelayBox v3.8.0（UI r33）子账号与临时测试号系统设计方案

> **适用基线**：RelayBox `v3.7.2`（UI r32，纯 Cloudflare Workers \+ D1 \+ R2 \+ Static Assets）  
> **目标**：在不破坏现有主管理员单密码体验的前提下，统一支持「**常规子账号（长期亲友/协作者）**」与「**临时测试号（限时限额体验/只读演示）**」两套模式。

## 1\. 核心架构与角色模型

统一由一张 `users` 表承载所有非主管理员账号，通过「角色 \+ 权限位 \+ 专属根目录 \+ 配额 \+ 过期时间」灵活组合：

| 身份 | 标识方式 | 目录范围 | 默认权限 | 过期 / 配额 | 管理后台可见性 |
| :---- | :---- | :---- | :---- | :---- | :---- |
| **主管理员** | `session.user_id = NULL`（沿用现有 `uploadPassword`） | 全站根目录 | 全部权限 | 无限制 | 全部可见 |
| **常规子账号** | `role = 'user'` | 绑定独立根目录（可自动创建） | 上传 / 删除 / 分享全开 | 默认永不过期，可选配额 | 屏蔽全部系统后台 |
| **读写测试号** | `role = 'guest'` | 绑定沙盒测试目录 | 上传 / 删除 / 分享可按需勾选 | 默认 24h–7d 自动失效 \+ 空间配额（如 100 MB） | 屏蔽全部系统后台 |
| **只读体验号** | `role = 'guest'` | 绑定展示目录 | `can_upload=0, can_delete=0, can_share=0` | 默认 24h–7d 自动失效 | 仅预览与下载 |

## 2\. 数据库变更（`migrations/0006_sub_accounts.sql` \+ 同步 `src/schema.sql`）

1. **新建 `users` 表**：  
   - `id TEXT PRIMARY KEY`  
   - `username TEXT NOT NULL UNIQUE COLLATE NOCASE`（登录名，2–32 位字母数字下划线短横线）  
   - `display_name TEXT NOT NULL DEFAULT ''`  
   - `password_hash TEXT NOT NULL`（纯 Web Crypto PBKDF2-SHA256，格式 `pbkdf2$100000$<salt_b64>$<hash_b64>`）  
   - `role TEXT NOT NULL DEFAULT 'user'`（`user` \| `guest`）  
   - `root_folder_id TEXT NOT NULL`（绑定的根目录 ID，创建账号时可自动新建）  
   - `quota_bytes INTEGER NOT NULL DEFAULT 0`（`0` 表示不限制）  
   - `can_upload INTEGER NOT NULL DEFAULT 1`  
   - `can_delete INTEGER NOT NULL DEFAULT 1`  
   - `can_share INTEGER NOT NULL DEFAULT 1`  
   - `enabled INTEGER NOT NULL DEFAULT 1`  
   - `expires_at INTEGER`（毫秒时间戳，`NULL` 表示永不过期）  
   - `note TEXT NOT NULL DEFAULT ''`  
   - `created_at INTEGER NOT NULL`  
   - `last_login_at INTEGER`  
2. **扩展 `sessions` 表**：  
   - `ALTER TABLE sessions ADD COLUMN user_id TEXT DEFAULT NULL;`  
   - `CREATE INDEX IF NOT EXISTS idx_sessions_user ON sessions(user_id);`  
3. **扩展 `files` 表**：  
   - `ALTER TABLE files ADD COLUMN owner_id TEXT DEFAULT NULL;`  
   - `CREATE INDEX IF NOT EXISTS idx_files_owner ON files(owner_id, trashed_at);`  
   - 用途：按用户单次 `SELECT owner_id, COALESCE(SUM(size), 0) AS used FROM files WHERE trashed_at IS NULL AND owner_id IS NOT NULL GROUP BY owner_id` 精确计算空间配额，严禁全表 `listAllFiles()`。

>   
> **实现红线**：`d1-meta.js` 中的 `updateUser` 必须沿用 `v3.6.1` 的原子部分字段 `push(col, val)` 模式，杜绝 `?` 占位符与 `.bind()` 参数错位。

## 3\. 鉴权与目录沙盒隔离（安全核心）

### 3.1 密码与会话（`src/core/lib/crypto.js` \+ `src/core/lib/auth.js`）

- **密码哈希**：在 `crypto.js` 新增 `hashPassword(plain)` 与 `verifyPassword(plain, stored)`，使用 Web Standard `crypto.subtle.deriveBits('PBKDF2', ...)` \+ 16 字节随机盐 \+ 常量时间比对（零 Node 依赖）。  
- **统一鉴权上下文 `getAuthContext(c, deps)`**：  
  - 读取 `fs_admin` Cookie → 查 `sessions`（保持 `expires_at > now` 原子校验）。  
  - 若 `session.userId` 为空 → `{ authed: true, isAdmin: true, user: null }`。  
  - 若 `session.userId` 非空 → 查 `users` 表并实时校验 `user.enabled === 1` 且 `(!user.expiresAt || user.expiresAt > Date.now())`；若已禁用或过期，直接返回未登录并清理 Cookie。  
- **向下兼容**：现有 `isAuthed(c, deps)` 仅对**主管理员**返回 `true`（防止误将管理员路由暴露给子账号）；所有需要同时支持子账号的路由显式调用 `getAuthContext(c, deps)`。  
- **登录接口 `POST /api/login`**：  
  - 未传 `username`（或为空）→ 走原主管理员 `uploadPassword` 校验。  
  - 传入 `username` \+ `password` → 查 `users` 表并校验 PBKDF2 哈希，失败同样计入 IP 防爆破限流。  
- **身份查询 `GET /api/me`**：返回 `{ authed, isAdmin, user: { id, username, displayName, role, rootFolderId, quotaBytes, usedBytes, canUpload, canDelete, canShare, expiresAt } }`。

### 3.2 路由权限分级与子树沙盒校验

- **仅主管理员（`isAdmin`）**：`/api/users/*`、`/api/pools/*`、`/api/settings/*`、`/api/audit/*`、`/api/github/*`、`/api/tokens/*`、`/api/stats`、`/api/announcement`、全站回收站管理、WebDAV。  
- **子树校验辅助函数 `assertFolderInSubtree(deps, folderId, rootFolderId)`**：  
  - 向上追溯 `folders.parent_id`（最多 16 层防环），确认 `folderId === rootFolderId` 或其祖先包含 `rootFolderId`。  
  - 子账号请求 `/api/files` 未传 `folderId` 时，强制默认定位到 `user.rootFolderId`；传入越界 `folderId` 直接返回 `403`。  
  - 子账号搜索（`?q=...`）仅匹配 `rootFolderId` 子树内的文件（可用 D1 递归 CTE `WITH RECURSIVE subtree` 查出子树 ID 集合后过滤）。  
  - 文件上传（直传 \+ 分片 init/complete）、新建子目录、移动、重命名、删除、创建分享、私有文件下载 `/f/:id` 全部校验目标位于子树内。  
- **权限位与配额拦截**：  
  - 上传前校验 `user.canUpload === 1`，若 `user.quotaBytes > 0` 则校验 `usedBytes + fileSize <= user.quotaBytes`（超限返回 `413`）。  
  - 删除/移入回收站前校验 `user.canDelete === 1`；创建分享链接前校验 `user.canShare === 1`。  
- **定时清理联动**：在 `scheduled` 定时任务中自动清理已过期用户的活跃 `sessions`。  
- **审计日志**：子账号的登录、上传、删除、分享操作均写入 `audit_logs`，`detail` 中带 `[user:<username>]` 便于主管理员追溯。

## 4\. 新增后端路由（`src/core/routes/users.js`）

全部路由要求 `isAdmin`：

- `GET /api/users` — 返回所有子账号/测试号列表，附带聚合后的 `usedBytes` 与绑定根目录名称。  
- `POST /api/users` — 创建账号；支持 `autoCreateFolder: true`（在根目录或指定父目录下自动创建同名文件夹作为 `root_folder_id`）。  
- `PUT /api/users/:id` — 原子部分更新（昵称、角色、配额、权限开关、过期时间、启用/禁用、重置密码）；禁用或改密时自动撤销该用户所有旧会话。  
- `DELETE /api/users/:id` — 删除账号并清除其 `sessions`（参数 `trashFiles=true` 可选将其上传文件移入回收站，默认保留文件）。  
- `POST /api/users/:id/kick` — 一键踢下线（删除该用户所有 `sessions`）。

## 5\. 前端 UI 设计（`public/index.html` → UI r33）

1. **登录弹窗升级**：  
   - 顶部增加可选输入框「账号（管理员留空）」，下方保留密码框；主管理员仍可直接输密码登录。  
2. **主管理员「账号管理」弹窗（`#usersModal`）**：  
   - 严格遵循移动端规范：`max-height: 86dvh; overflow-y: auto; overscroll-behavior: contain`，新增表单默认折叠，禁止原生 `window.confirm()`（统一走 `uiConfirm`）。  
   - **一键预设模板**：新建时提供「常规子账号」「24h 读写测试号」「7天只读体验号」三个快捷按钮，自动填充角色/权限/有效期/配额。  
   - **凭据一键复制**：创建或重置密码后弹出可复制的凭据摘要（站点链接、账号、密码、有效期、配额），方便直接发给别人。  
   - **账号卡片**：展示用户名、角色徽章、绑定目录、空间用量条（如 `24.5 MB / 100 MB`）、到期倒计时、启用开关，以及「踢下线 / 重置密码 / 编辑 / 删除」操作。  
3. **子账号 / 测试号工作台视图**：  
   - 顶栏隐藏所有管理员按钮（存储池、设置、GitHub 拉取、统计看板、审计日志、账号管理、收件箱管理），显示身份状态胶囊（如 `测试号 · demo01 · 剩 22h · 12/100MB`）。  
   - 文件列表根节点锁死为 `user.rootFolderId`，面包屑根节点显示为「我的空间（或目录名）」，不暴露上级目录。  
   - 按权限位动态显隐 UI：`!canUpload` 隐藏上传拖放区、`!canDelete` 隐藏删除按钮、`!canShare` 隐藏分享按钮。

- **自动化测试**：现有 `npm test`（`v340-verify.mjs` 41/41 \+ `test-batch1-d1.js` 14/14）全部通过，并新增 `users` 权限隔离/子树越权/配额超限/过期自动失效单测。
